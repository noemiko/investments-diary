# Phase 4 UI verification

Use the running [local app](http://127.0.0.1:4321) and test holdings in USD/PLN/EUR wallets. The automated checks use disposable local fixtures; no production migration or deployment has occurred.

1. Open **New investment**, choose a wallet and search for a Yahoo stock/ETF. Select the intended company and exchange, then enter buy price/date and category and save. A typed name without selection must not save. Search, selection and Save must not download a quote; entered price, date, quantity and reason must survive search/select and validation failures. The saved holding should show its selection and enable the dashboard download action. Public examples are AAPL in a USD wallet and PKO.WA in a PLN wallet.
2. Click dashboard **Download prices** for the new holding. The first download verifies trading currency/timezone before applying a quote. An incompatible currency must report the problem and retain saved values; it must not convert amounts or apply the wrong currency. Check progress, per-listing outcomes, retry information and refreshed saved values. Reloading, focusing the page or waiting must not start a download.
3. For an existing unlinked holding, choose **Link stock listing** on **Your positions**. It should jump to **Stock listing** without downloading anything. Type an unsaved manual price and sale price. Search, explicitly download a candidate quote, inspect exchange/currency/timezone and confirm. The original diary label and both unsaved inputs must remain unchanged. Confirmation must not download again.
4. Save a manual correction. Its source should read **Temporary manual correction** while the cached market timestamp is equal to or earlier than the database save time. Re-downloading the same market quote must not replace it. Automated database checks cover the strictly later timestamp boundary; a closed market may supply the same quote repeatedly.
5. Move an open or closed test position to another owned wallet. Only matching wallet denominations are offered. Existing wallets that had no currency now use USD, and no currency attestation is required. Check the wallet link and current membership, unchanged position facts and retained unsaved form input. Previous observations must remain unchanged.
6. Open wallet history. Earlier observations that lacked a currency label now inherit their wallet currency and appear in the ordinary currency chart. Their recorded amounts and dates remain unchanged. New captures use saved effective values and record source coverage; no provider request occurs during capture. If no observations exist yet, the page explains that state rather than inventing historical points.

Provider timeout and retry messages, retained prices and preserved inputs have also been checked with deterministic browser fixtures. There is no need to induce a real rate limit. If the provider is unavailable during your walkthrough, its failure must leave the saved price visible and provide an explicit retry path.
