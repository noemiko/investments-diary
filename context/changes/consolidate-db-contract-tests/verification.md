# Verification: consolidate-db-contract-tests

## Assertion map

Every assertion in the six in-scope scripts, with where it goes. Line numbers refer to the scripts as they stand before Phase 3 deletes them.

- **Classes.** **P** = permanent rule of the final schema. **T** = one-time transition or intermediate schema state. **F** = sanity check on the test's own setup.
- **Destinations (re-planned 2026-11-02, Phase 2).** The database test keeps only owner-only access and the grant invariant. Each **P** row goes to one of:
  - `contract/access.mjs:<line>`: RLS, isolation, foreign writes and anon reads, checked for every table in `public`;
  - `contract/grants.mjs:<line>`: the policy-grant rows;
  - "left to smoke/Vitest", citing the smoke step (`scripts/testing/smoke.mjs`) or the Vitest file:line (`tests/database/`);
  - "not covered (accepted, re-plan 2026-11-02)" where neither smoke nor Vitest checks the rule.
- **T** and **F** rows stay "dropped", with the reasons given in Phase 1.
- **42501 rows.** Checks that passed only because a hand grant masked production privileges now expect exactly `42501` in `contract/access.mjs`, and B's rows are fingerprinted unchanged afterwards (`contract/access.mjs:169–170`).
- **Foreign UPDATE.** The expected outcome comes from the catalogue: 0 rows on tables where authenticated holds an UPDATE privilege (`positions`, `reason_categories`, `wallets`), exact `42501` on the rest.

## Early removals (2026-11-02, Phase 1, owner request)

Two scripts were deleted in Phase 1 instead of Phase 4, after a review of which database tests are essential:

- `test-policy-grants.mjs` (`test:grants-db`): fully superseded by `contract/grants.mjs`, which passed and went red on a deliberate `grant select on public.wallets to anon`. Its CI step now runs `test:contract-db`.
- `test-wallet-database.mjs` (`test:wallet-db`): checked a four-migration schema only and passed its hard-delete and anon checks through a hand `grant all`, so it protected nothing on the current schema. Its CI step in the push-only `smoke` job was removed. Its permanent rules are re-mapped above (Phase 2 re-plan): access rules to `contract/access.mjs`, the rest to smoke/Vitest or "not covered (accepted)".

Plan criteria that name these commands (2.4 `test:grants-db`; 4.4 grep) no longer apply to them.
