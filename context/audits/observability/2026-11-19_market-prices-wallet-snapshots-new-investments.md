# Investments Diary observability audit

## 1. Summary

- Market search and quote reporting throws away failure reasons already present in the service result. Responders can see an event and still be unable to distinguish a deadline, an unusable quote, or a provider outage.
- The investment write path classifies whole families of database rejections as form validation. A database contract regression can reject an otherwise valid investment with no application log or event.
- Browser catches convert transport and response-contract failures into UI warnings without reporting them. The PostgreSQL snapshot job has its own execution history and can fail while wallet pages continue serving live values.
- Start by carrying closed-enum market stages and failure reasons through the existing reporter. This covers both search and downloads while keeping queries, financial values, and provider payloads private.

## 4. Systemic root causes

1. **Failure translation discards diagnostics.** The market adapter and service layers keep enough information to choose a UI fallback, while reporter calls collapse it to a synthetic stack and generic operation. Response-level PostgREST status is similarly lost when call sites pass only the error object. See MP1 and P2.
2. **Normal-looking results erase unexpected states.** Download branches turn expired work into due items and ambiguous identity into a provider-style quote failure. Position writes assign all check violations to the validation path. See MP2, MP3 and NI1.
3. **Reporting coverage ends at the boundary that owns the failure.** Browser catch blocks handle errors before global capture, and the snapshot SQL runs on the PostgreSQL scheduler. See P1 and WS1.
4. **Request context can disappear between capture and scrubbing.** The search route is absent from the allowlist, and automatic server capture occurs outside the child scope that owns the app request tags. See P3 and P4.

## 6. Recommended fix order

1. Carry safe market failure reasons, stages, status, and the search route through the existing reporter. Reuse the same vocabulary for deadlines and ambiguous cache identity, with at most one summary per affected batch. Covers MP1–MP3 and P3.
2. Identify expected save rejects precisely and preserve response status at database error boundaries. Covers NI1 and P2.
3. Emit browser telemetry for transport and response or fragment contract failures, with deduplication against handled server errors. Covers P1.
4. Preserve request correlation on automatic server capture. Covers P4.
5. Connect the snapshot scheduler to a job-level failure and missed-run signal. Validate failure, no run, and legitimate zero inserts as separate cases. Covers WS1.
