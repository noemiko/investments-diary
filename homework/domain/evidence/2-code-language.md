## One concept, many names

- **Position = investment = holding = entry** (evidence). Code identifiers and tables always use `position`. UI copy uses "New investment" / "Save investment" for creation (`dashboard.astro:61`, `PositionForm.tsx:544`), "positions" for lists (`dashboard.astro:47`, `deleted.astro:26`), "Investments" on the wallet page (`wallets/[id].astro:141`), and "holding(s)" in the price-download copy (`DownloadPrices.tsx:29,68,75`). "Entries" also appears (`new.astro:137` "Your entries are preserved", which there means form fields). The SQL comment "existing draft investments" (`20261102120000_…sql:2-3`) adds a fifth word, "draft", which has no identifier **[comment]**.
- **Wallet observation = wallet snapshot** (evidence). The table, type and function say `snapshot` (`wallet_snapshots`, `WalletSnapshot`, `capture_wallet_snapshots`). The cron job, UI and comments say `observation` (`'wallet-daily-observations'` `register_…job.sql:15`; `WalletTimeline.tsx:67`; `wallet_snapshots.sql:1` "immutable observations"). The column `observation_day` mixes both words.
- **Stock identity: instrument / listing / target / selection / receipt / lookup** (evidence). One idea, "which security this position is", carries six names. `positions.instrument` is a text label (`create_diary_core.sql:29`). `market_listing_targets` is the "selection" (`pending_stock_selections.sql:1` comment "Search proves a selectable identity"). `market_selection_receipts` is a 30-minute proof of a choice (`:22-27`). `positions.market_listing_id` is a *confirmed* listing that points at `market_quote_cache` (`market_price_persistence.sql:100-104`). `market_listing_lookups` is a retired existing-position lookup (`listing_lookup_receipts.sql:3`; retired `20261102130000_retire_listing_lookup_rpcs.sql:10-13`). On the UI side, "pending" covers the target before it has been verified (`PositionValuation.pendingSelection` `src/types.ts:264`; view columns `pending_symbol…` `pending_stock_selections.sql:151`).
- **Manual price = current price = manual entry = manual correction / override** (evidence). The column is `current_price` (`add_position_current_price.sql:13`) and the UI header is "Current price" (`positions/[id].astro:220`). `selected_source` distinguishes `manual` from `manual_override` (`market_price_persistence.sql:233-236`). UI labels: "Manual price", "Temporary manual correction", "Manual correction", "Saved manual entry" (`PriceContext.astro:13-22,94`).
- **Close = sale = sell** (evidence). The operation is `closePosition`, the columns are `sell_price`/`sell_date`, the source value is `'sale'`, and the UI shows "Close position", "Sale" and "Closed" (citations in the table above).
- **Realised vs closed, open vs unrealised** (evidence). The code uses `realised_change`/`realisedCount` and `open_change`/`openCount` (`wallet.ts:12-19`, `wallet_snapshots.sql:9-12`). The word "unrealised" has 0 hits in UI files. UI says "Open gain/loss" (`WalletValue.astro:42`).
- **User = author = owner = account** (evidence). Identifiers say `user_id` and `locals.user`. TS prose says "author" (`positions.ts:23`, `wallets.ts` comments). SQL and endpoint prose says "owner" (`retire_listing_lookup_rpcs.sql:2`). Scripts say "account" (`create-user.sql:1`).

## One name, many concepts

- **`reason`** (evidence): (a) the investment rationale: `reason_text`, `reason_categories`, "Reason" (`create_diary_core.sql:12,37`); (b) a machine failure code: `MarketDataFailure.reason` / `MarketDataFailureReason` (`src/types.ts:205-211`), `MovePositionResult.reason` (`positions.ts:333`), JSON `{ ok:false, reason }` (`endpoint.ts:39-63`), `positionsRead.reason` (a rejected promise, `dashboard.astro:36`). This collision is the sharpest one, because "reason" is the core business word.
- **`result`** (evidence): (a) a position's gain/loss: `positionResult`, the "Result" column (`result.ts:27`, `PositionsSection.astro:82`); (b) an operation outcome: `CreatePositionResult`, `ClosePositionResult`, `MarketSearchResult`, `ParsePositionResult` (`positions.ts:35,299`, `src/types.ts:218`).
- **`current_price`** (evidence): in the DB it is the manual price only (`add_position_current_price.sql:13`). After `composeEffectivePrice` the same TS field carries the *selected effective* price, which may be an automatic quote (`effective-price.ts:138-139`: `current_price: row.sell_price === null ? selected : row.current_price`). The manual value is moved to `valuation.manualPrice` (`effective-price.ts:94`).
- **`listing`** (evidence): (a) a search candidate with no currency (`MarketListingCandidate` `src/types.ts:169`); (b) a verified listing with currency and timezone (`MarketListing` `:184`, comment "Search does not establish currency"); (c) `market_listing_id`, which is a FK into `market_quote_cache`, not into `market_listing_targets` (`market_price_persistence.sql:103-104`).
- **`outcome`** (evidence): `refresh_outcome` is a persisted quote refresh state (`market_price_persistence.sql:58-59`). `MarketPriceDownloadItem.outcome` is a per-click result that adds `due`, `cooldown`, `refreshing` and `incompatible_currency` (`src/types.ts:236-237`).
- **`source`** (evidence): `selected_source` means which price was chosen (`market_price_persistence.sql:232`). `source_name` and `source_interval_minutes` describe the data feed (`:56-57`). "Source coverage" counts automatic and manual prices in snapshots (`effective_snapshots_and_wallet_moves.sql:8`, `WalletTimeline.tsx:199`).
- **`value`** (evidence): wallet value (`WalletValueResult.value` `wallet.ts:9`, `wallet_snapshots.value`) versus raw form values (`PositionFormValues` `src/types.ts:88`).
- **"Open"** (evidence): an open position (`PositionResultValue.kind "open"` `result.ts:13`) versus open-position gain (`open_change`, the "Open" label `WalletSummaryCards.astro:52`).

## Implicit concepts

- **Open / closed position state** (evidence): there is no status column. "Closed" means `sell_price`/`sell_date` are both non-null (`close_position.sql:5`; `result.ts:28`; filter `.is("sell_price", null)` `positions.ts:313`).
- **Deleted / active** (evidence): only `deleted_at` is non-null (`create_diary_core.sql:18,39`). Wallets carry `deleted_at` but a check forbids setting it (`wallets_no_soft_delete check (deleted_at is null)` `20261019150000_prevent_wallet_deletion.sql:4`), so "wallet deletion" exists only as a reserved column.
- **Pending (unverified) stock selection** (evidence): exists only as `market_target_id` set while `market_listing_id` is null (index `positions_pending_target` `pending_stock_selections.sql:56-57`) and as `pending_*` view columns.
- **Lease / cooldown** (evidence): concurrency and back-off live as column pairs `lease_token`/`lease_until` and `cooldown_until` on three tables (`market_price_persistence.sql:61-63,69`; `pending_stock_selections.sql:14-16`), with `claim_*`/`finish_*`/`release_*` RPCs.
- **Counted / not counted** (evidence): positions excluded from wallet value (missing quantity or missing price) are only the counter `notCounted` / `not_counted` (`wallet.ts:20-21`, `wallet_snapshots.sql:13`). UI: "Counted / excluded" (`WalletTimeline.tsx:223`).
- **Freshness ("as of")** (evidence): `asOf` is the oldest counted open quote date (`wallet.ts:22`, `wallet_snapshots.as_of`). UI: "Open prices as of …" (`wallet.ts:94`).
- **Acknowledgement of a full close** (evidence): a form-only checkbox `acknowledgement` (`src/types.ts:135,141`; `positions/[id].astro:344-354`), with no persisted counterpart.
- **Reason lock** (unknown → evidence of absence): the SQL comment says "Reason lock (FR-008): enforced in S-07. This migration adds no trigger for it" (`create_diary_core.sql:4-5`) **[comment]**. Searching `src/` and `supabase/migrations/` for `reason_text` and `lock` finds no update path and no trigger. `reason_text` is written only on insert (`positions.ts:289`). So the lock is enforced *by omission*: there is no edit operation at all.
- **Category rename/removal** (evidence of absence): `reason_categories.deleted_at` exists (`create_diary_core.sql:18`). No service, route or UI updates or deletes a category: grep across `src/pages` and `src/lib/services` found only `listCategories` and `findOrCreateCategory`.

## Where business logic lives

- **No domain layer** (evidence): `src/types.ts` holds `Pick<>` projections of DB rows and literal unions, and has no behaviour. Logic is split between pure TS functions in `src/lib/*.ts`, thin services in `src/lib/services/`, and SQL.
- **Position result and wallet value** are implemented twice: TS `positionResult` / `walletValue` (`result.ts:27`, `wallet.ts:31`, "The single definition of a wallet's value") and SQL inside `capture_wallet_snapshots` (`effective_snapshots_and_wallet_moves.sql:15-45`). The docstring claim of a "single definition" (`wallet.ts:26-29`) holds only for TS **[inference]**.
- **Price selection rule** (manual override until a newer market quote): in the database view only (`market_price_persistence.sql:220-237`). TS consumes it: "Every read surface consumes the same SQL selection" (`effective-price.ts:43`).
- **Stock selection immutability, receipt validity, instrument overwrite**: DB trigger `guard_position_selection` (`20261102080240_…sql:3-28`), plus a 409 in the route handler (`endpoint.ts:44`).
- **Currency match** (listing vs wallet, move between wallets): DB triggers and RPC (`guard_position_listing` `market_price_persistence.sql:109-125`; `move_position_to_wallet` `set_wallet_denominations.sql:47`).
- **Ownership / privacy**: RLS `*_own` policies on every table, plus composite FKs `(id, user_id)` so a position can only use its owner's category and wallet (`create_diary_core.sql:19-20,40-41`).
- **Soft-delete-only**: DB (no delete policy, `create_diary_core.sql:67`) plus service updates of `deleted_at`.
- **Field validation** (future dates, decimals): `src/lib/validation/*.ts`. The migration comment says future buy and price dates are rejected "in application code, not by a check constraint" (`create_diary_core.sql:6-8`) **[comment]**.
- **Confrontation filtering** (same category, case-insensitive name match for a new category): pure TS `confrontation.ts:17-40`, run in the UI island and on SSR.
- **Daily observation capture**: DB function plus pg_cron at `0 0 * * *` UTC (`register_…job.sql:15-24`). Snapshot immutability: no write grants (`wallet_snapshots.sql:27-28`).

## Unknowns
